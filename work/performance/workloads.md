# 性能测量协议草案

当前 profile 是 [`performance_profile.json`](performance_profile.json)，状态为 `DRAFT_NOT_FROZEN`；[原始记录结构](raw_schema.json) 规定了采集字段。已有探索性测量不能直接当作冻结门槛或正式产品性能结论。

## 对照与验证

- A0：所选框架 backend 的同语义直接实现。
- A1：既有同语义封装的固定测试负载；其既有快路属于基线。
- A2：MeguvizHook 的同语义实现。
- A3：单独选择的可选优化；不把 A3 的结果混同于默认实现。

先用同一实现的 A/A 测量估计波动，再按实际场景确定和冻结阈值、样本量、设备、框架、制品及配置，之后才进行正式 A/B。正确性优先：异常身份改变、重复调用原方法或其他语义回归不能用平均速度抵消。区分源码推导、桌面模型、代理测试和实际设备测量。

候选指标包括 callback CPU、任务延迟分位数、安装、冷启动和资源预算；未定义或不可测量的值保留为空。普通 Hook 热路径不隐式增加 JNI 或 IPC；可选诊断传输由调用方显式启用，不能混入普通路径成本。各场景的旧探索数据、运行条件和置信范围不自动适用于其他设备、框架或工作负载。
