# Android 时钟读数诊断

`verify_clock_probe.py` 仅核验一次明确选定的 `MeguvizHookClock` 设备日志。它不启动设备、不修改
原始日志、不认证日志来源或设备身份，也不评估性能门槛。原始日志可能含其他进程的信息，应留在
本地私有证据目录，并另外保存设备、进程与采集方式的可信证据。

```text
python tools/performance/verify_clock_probe.py <原始-threadtime-日志> \
  --run-id <标准小写UUID> --pid <进程PID> --tid <工作线程TID>
```

每个可辨识的目标日志行必须是完整 UTF-8、有效 JSON、无重复字段，且被选中 run 的 threadtime
前缀 PID/TID 与 JSON 和命令行一致。无关行中的非 UTF-8 字节不会改变原始内容或导致整份日志被
拒绝；可辨识的目标标签损坏、非 UTF-8 目标行或任何异常字段均拒绝。
同一个 PID 的其他 run 也被拒绝：单进程只接受一次诊断，PID 复用或混合日志必须另外取证。

事件按 `start`、从 0 起连续的 `warmup`、从 0 起连续的 `sample`、`end` 排列。CPU 和 wall
时间分别按记录顺序检查每组前后及跨组的非倒退性；相等合法。负值或倒退必须按设备端协议报告
失败，即使随后缺少 `end` 也不降级为普通截断。所有读取原值、阶段和序号以及原始日志 SHA-256
均在可解析结果中保留；原始文件不会被改写。

返回状态和进程退出码：

- `observed` / 0：两种时钟的采样阶段都至少观察到一个正的成对间隔。
- `unresolved` / 2：采样阶段至少一种时钟的成对间隔全部为零；两个时钟分别报告观察状态。
- `incomplete` / 2：缺失所选 run 或完整结束事件，且没有已观察到的时钟失败。
- `clock_failure` / 1：设备报告 CPU/wall 时钟不可用或倒退；保留失败原值和结束事件是否存在。
- `invalid` / 1：标签编码、事件字段、身份、顺序或失败报告与协议矛盾；文件可读取时同时报告
  原始日志 SHA-256。

输出中的零/正间隔数量及最小正间隔**只描述本次连续读钟的观察**，包括读钟本身和周边调用成本；
它们不代表时钟的真实分辨率、准确度、纯 callback CPU 或单次调用延迟。不要自动扣除这些间隔，也
不能据此冻结阈值或宣称 `GATE-002` 通过。
